## Next: the five Stoat issues from today

One coherent cluster — a suite that a monitor can ask to run things — plus one attribution follow-on.
Read them in this order; #390 is the one that decides the shape.

- **#390 Resident runner** — a suite that takes run commands from a monitor over SSE. Shape already
  decided in the issue: the **runner stays a client**, connecting out to the same 5525 origin every
  publisher already probes and *asking* for work, so a monitor can never make a runner do anything.
  Every message is a CloudEvent. This is the Bobcat half of Stoat's interactive execution.
- **#391 Run and list specifications by identity in either lane** — `{Feature}/{Scenario}` maps to
  `--filter-uid` for a Gherkin host, but a projected suite's platform uid is the *test framework's*,
  so an identity has to be translated to a method/class filter through the generated declared-steps
  manifest, which already knows identity ↔ method. Only the runner knows its own lane.
- **#392 `run_started` carries the command that caused it** — a trailing optional `Command`, exactly
  the shape `Tag` and `Session` already have. **Session landed today in b349c7d**, so this is the same
  edit in the same four publishing sites; copy that commit.
- **#393 Warm mode (Gherkin suites)** — command after command inside one booted host. Cold stays the
  default; warm is opted into per command and offered only by a runner that registered it.
- **#394 Investigate warm runs for projected suites** — explicitly an investigation, not a commitment.
  Projected suites are cold-only in #390 because their test framework owns the process; the candidate
  is the platform's server mode, which is undocumented and has moved between versions (see the #43
  spike's warning, which is why `IWorkerClient` exists).

Worth knowing before starting: `MonitorPublisher.TryConnect()` already probes 5525 once with a tight
timeout and returns null when nothing answers, and `MonitorRunInfo.Discover` already reads the
environment. The never-slow-never-fail invariant on the publisher applies to anything added here.

## What today changed that a reader should know

- **A projected run prints its specifications by default** when a terminal is attached and nothing is
  listening on the wire. `BOBCAT_SPEC_CONSOLE` overrides in **both** directions, which made the
  setting a tri-state. `Bobcat.Xunit.Tests` opts out in a module initializer — it drives
  `MarkerStepRun` for real to test the adapter, so its recordings are fixtures, not specifications.
- **A comparison renders in the sentence**, where its value sits, not on a line below. The join is the
  placeholder name, so `Check("Sum", …)` belongs where `{sum}` was. A cell matching no placeholder
  keeps its line.
- **Every value is now bound at run time, literals included.** A positional literal used to be
  substituted at compile time, which left no span — so whether a cell rendered inline depended on
  whether the caller wrote a positional literal or a named argument. Three generator tests pinned the
  old rule and now pin this one.
- **A grid's Status column appears only when something was judged**, and tells four outcomes apart:
  `OK` green, `ORDER` yellow (values agreed, position did not), `MISSING` red, `EXTRA` red (was
  yellow). An arrange table has no Status column at all.

## How to run everything

```bash
dotnet build bobcat.slnx
docker compose up -d                                        # Postgres on 5445
export TESTINGPLATFORM_TELEMETRY_OPTOUT=1
for d in src/*.Tests; do p=$(basename $d); ./$d/bin/Debug/net10.0/$p; done

dotnet run --project src/Bobcat.Gherkin.Samples/ -- run      # 18 of 30 red on purpose
./src/Bobcat.Xunit.Samples/bin/Debug/net10.0/Bobcat.Xunit.Samples   # 24 of 41 red
```

**To see a projected spec report you need a terminal and no console on 5525.** Stoat listens there
when it is running, and the default is deliberately quiet then — which cost half an hour of confusion
today. A tool that captures output is also not a terminal, so from an agent use a pty:

```python
import os, pty
os.environ["BOBCAT_MONITOR"] = "0"          # nothing on the wire
pty.spawn(["./src/Bobcat.Xunit.Samples/bin/Debug/net10.0/Bobcat.Xunit.Samples"])
```

Or just set `BOBCAT_SPEC_CONSOLE=1`, which wins over both conditions.

**Relative dates resolve in UTC.** Run in the evening US Central, `TODAY` is tomorrow's date — the
Sets grids read `2026-10-01` on 2026-09-30. Not a bug; worth knowing before chasing an off-by-one.
